# 公众号 AI Studio 2.1.3 数据库迁移与回滚

## 版本说明

2.1.3 没有新增数据库字段，数据库 schema 版本仍为 `212`，可直接使用 2.1.2 数据库。文章分页、搜索和总数统计建立在现有字段和索引上，不需要破坏性迁移。

## 从 2.1.0/2.1.1 升级

首次启动仍由 2.1.2 引入的迁移器执行：

1. 对原数据库执行 `PRAGMA integrity_check`。
2. 使用 SQLite Backup API 创建一致性备份。
3. 执行 schema 212 迁移和来源快照重建。
4. 对迁移结果再次执行完整性检查。
5. 失败时从备份恢复原数据库。

备份文件名称仍使用：

```text
studio.db.pre-2.1.2-v<旧版本>-<UTC时间>.bak
```

这是迁移目标 schema 212 的固定命名，不应因应用包版本升级为 2.1.3 而改名。

## 主密钥

数据库与 `data/.master.key` 必须成对备份。Windows 首次读取旧 32 字节主密钥时会迁移为当前用户 DPAPI 格式；该过程不改变实际加密密钥，因此原数据库中的密文仍可解密。

## 验证

```bash
python verify_capacity.py
```

Windows：

```text
verify_windows_dpapi.cmd
```

迁移和回滚不得只复制 WAL 文件；应先停止服务，再备份主数据库、主密钥和必要的 `-wal/-shm` 文件，或使用 SQLite Backup API。
